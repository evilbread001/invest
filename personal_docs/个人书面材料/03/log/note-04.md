# 新异常线索与补充检查实施计划

**目标：** 暂缓当前检查并报告另一异常时，DSH 可查询原树、生成待确认补查卡，补查证据与原引擎结论隔离。

**架构：** 保留原 BPMN/OWL 路由。Python 从已执行快照的依赖图导出全部 TEST 目录及来源；仅当前活动父节点下的单 TEST 同层条件允许提前收集观察，其余只记录线索。该规则证明逻辑范围，不代表现场作业安全许可。Node 保存补查任务及独立证据；原树真正激活同一条件后，由工程师再次确认复用，不自动填答。

**技术栈：** 既有 DSH、TypeScript、Python、原生浏览器 UI；不添加依赖，不修改生产仓库、不提交 git。

**依据：** 本会话已确认的“暂缓＋另一个异常”方案；用户要求直接实施。

## 任务与验证
- [ ] 在 `engine/worker.py` 从快照 dep_graph 导出有作用域的检查目录，包含 TEST 名、选项、来源、所属分支、单条件标识和允许补查原因；`src/engine.ts` 校验输出。
- [ ] 在 `tests/engine.test.ts` 先写失败测试：同层翘曲可补查、深层应力不可提前派发；暂缓与补查一次确认；补查结果不改变快照；原树激活后再次确认复用；去重、非法值、过期提议与跨工单隔离。
- [ ] `src/diagnosis.ts` 保存独立线索及补查任务，创建/恢复/重启保持记录；已生成正式任务不重复补查；未知反馈不作为明确证据。
- [ ] `src/diagnosis-plugin.ts` 和 `src/runtime.ts` 提供线索记录、目录查询及补查提议。模型不能确认、不能编造候选、不能越过逻辑依赖。
- [ ] `public/app.js` 显示暂缓阻塞说明、候选入口、补查标识、创建确认和结果复用；补查结果提交要求现场对象及作业条件人工确认。
- [ ] 运行全量 Node/Python 测试、类型及 JS 语法检查；真实 LLM 验证“看不了焊盘但发现翘曲”，浏览器验证确认、填报与主路径不变；更新说明及项目记录。

## 重点边界
- 深层条件、复合条件不可当成无前置的独立检查；不以同层关系替代实际安全条件。
- 新线索不等于检查事实，更不等于根因；目录无匹配时仍可存为未验证线索。
- 暂缓和补查组合一次确认，避免确认其一使另一提议过期。
- 补查与正式检查必须按工单、树版本、条件节点匹配，不能只凭同名跨分支复用。
- 源码变更后旧快照仍按版本规则拒绝推进，新功能演示需新建工单。
