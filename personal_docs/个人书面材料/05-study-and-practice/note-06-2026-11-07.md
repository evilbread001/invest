### Shared speaking structure / 通用讲述结构

1. Background: who had what problem? / 背景：谁遇到了什么问题？
2. Objective and outcome: what was improved, and how was it assessed? / 目标与结果：希望改善什么，如何判断？
3. Ownership: what did I implement? / 职责：我实现了什么？
4. Technical choices: which technique addressed which difficulty? / 技术：用什么解决哪个难点？
5. Boundary: what is implemented, simulated, estimated, or awaiting confirmation? / 边界：哪些是实现、模拟评测、测算或待核实内容？

Aim for 300–450 Chinese characters per first-pass explanation, then time it aloud. Do not recite file names or introduce every feature. Passing means a listener can identify the problem, your work, and why the selected techniques helped.

第一版每个项目约 300–450 个中文字，以实际口述计时为准。不背文件名，不介绍所有功能。听者能知道问题、你的工作和技术作用，即达到今天的标准。

### Project 1: production diagnosis / 项目一：产线诊断

Background: engineers repeatedly gather data across systems and rely on expert knowledge to investigate process-quality exceptions. Objective: automate repeatable analysis and reuse diagnostic experience without forcing engineers to finish irrelevant checklists.

背景：工程师跨系统查数，依赖专家经验排查制程质量异常。目标：自动完成重复分析，复用诊断经验，同时避免把排查流程变成必须完成的打卡表。

- BPMN + fault-tree executor: organize stages, conditions, and wait/resume behavior. / BPMN 与故障树执行器：管理阶段、条件判断及等待恢复。
- Python/SQL analysis functions, including 3σ and commonality analysis: automate data checks. / Python、SQL、3σ 与共性分析函数：自动完成数据核查。
- DSH + Skill + Tool Calling: support exploratory diagnosis and structured feedback in the local prototype; connect document-based tree generation with conversational editing and manual publication. / DSH、Skill、Tool Calling：在本地原型中支持开放排查及结构化反馈，并联动文档建树、对话编辑和人工发布。

Follow-ups: Why not let the LLM own all routing? How does natural-language feedback become a controlled state update?

技术追问：为什么不让 LLM 控制全部流程？自然语言反馈如何变成受控状态更新？

### Project 2: customer service / 项目二：售后客服

Background: service knowledge is fragmented, user wording differs from technical terminology, and ticket collection spans multiple turns. Objective: retrieve applicable guidance and collect usable service-ticket information, reducing unnecessary human transfer.

背景：售后知识分散、用户表达与专业术语不同，填单信息分多轮提供。目标：检索适用方案、收集可用工单信息，减少不必要的转人工。

- PostgreSQL/pgvector + literal matching + weighted RRF: combine semantic and textual retrieval across card fields. / PostgreSQL、pgvector、字面匹配、加权 RRF：组合知识卡多字段语义与文字召回。
- Similar-question expansion + optional reranking: address wording mismatch and candidate ordering. / 相似问扩充、可选重排：改善表达差异和候选排序。
- Skills + tools + per-device business state + VLM findings: support multi-turn collection and device-specific context. / Skill、工具、按设备保存的业务状态、VLM 结果：支持多轮采集与设备隔离。
- Simulated regression and bad-case analysis: identify retrieval, tool, field, and simulator failures. / 模拟回归与 Bad Case 分析：定位检索、工具、字段和模拟器问题。

Follow-ups: What happens after an unsuccessful retrieval? Why does the agent need structured state if conversation history already exists?

技术追问：检索无结果后怎么处理？已有聊天历史，为什么还需要结构化状态？

### Project 3: press-fit curves / 项目三：压装曲线

Background: endpoint checks and fixed envelopes do not fully describe process-curve shape; manual boundary adjustment is costly. Objective: identify suspicious pressure–displacement curves and support human review.

背景：终值和固定判异框不能充分描述过程曲线形态，人工调整边界成本高。目标：识别可疑压力—位移曲线，辅助现场复判。

- Key points + 3σ: statistically calibrate monitoring regions. / 关键点与 3σ：统计标定监控区间。
- Segment features + Isolation Forest: identify unusual local-stage characteristics. / 分段特征与孤立森林：识别局部阶段特征异常。
- PyTorch LSTM autoencoder: learn normal sequence patterns and score reconstruction deviations. / PyTorch LSTM 自编码器：学习正常序列模式，以重构误差识别偏离。
- Edge inference + anomaly cards: deliver results for manual review and traceability. / 边缘推理与异常推卡：支持人工复判与追溯。

Follow-ups: Why combine rules, features, and a sequence model? How do you set thresholds and assess false positives and false negatives?

技术追问：为什么结合规则、特征和序列模型？阈值怎么定，误报和漏报怎么评估？
