# 产线诊断工作台 · DSH Demo

一个独立的“任务卡片＋对话协作”原型。**真实复用 DeepSeek Harness 的 AgentLoop、ToolRuntime、SessionStore 和 Cordis 插件，不用手写循环假装 DSH。**

本机现已接入 **原 lads BPMN/OWL 执行代码、原 PCBA `diagram.bpmn` 和少锡故障树定义**。通过独立 Python 进程运行，检查卡片由真实执行队列生成，提交反馈会恢复原引擎。**事件为合成数据，未连接 MES，未执行生产 UDF，未推卡、控线或发布生产故障树；已支持 Demo 本地增量发布。** 原四任务模拟状态机保留为可选模式。

**当前确认版产品与技术说明：** `/Users/gerui1/production-diagnosis-dsh-demo/docs/current-version-2026-10-19.md`。集中说明产品闭环、DSH/原引擎职责、对话推进状态、补全审批、验证及未接入范围；后续项目讲述优先参考此文。

## 当前接入状态（2026-10-19）

- **协作版：** 中间栏优先展示假设、证据及缺口；原故障树保留为辅助路径，不再把查完全部节点当成唯一出口。
- **新异常与补查：** 查询原树 TEST 目录，当前活动父节点下的单 TEST 同层项可生成待确认补查卡；可在同一提议中暂缓当前任务。补查结果独立保存，原树激活同一条件后可由人工再次确认复用；深层/复合条件不自动越过前置。
- **验证工具：** 批次不良率与换料前后对比从 `fixtures/pcba-verification.json` 的逐板合成记录计算，带分母、样本 ID、数据来源和局限。不是 MES 取数或当前工单真实生产数据。工程师验证记录保留支持/反对/不确定关系，系统不独立核验口述。
- **专家出口：** 用户提供验证过程后，模型可起草结论；工程师核对全部证据、反对记录和未查项并署名确认，才结束本次诊断。结束后冻结诊断写入，保留原树等待状态及未查项，报告区分专家确认与树推断；不控线、不批准生产放行。Demo 署名不是身份鉴权。
- **实测：** 最新归档为 26 项 Node 测试、4 项 Python 测试、类型/JS 语法检查通过；此前真实模型三轮完成补查、合成样本分析、人工验证记录与专家结论草稿，10 次工具调用均成功，确认前不自动结束。新增真实模型联调验证候选路径生成、两次人工确认与本地发布。
- **知识补全：** 树外专家结单后自动生成候选路径，人工编辑确认草稿，再单独确认本地发版；新工单加载增量，旧工单保留原记录。生成和审核不会推进已结束工单的原树。
- 引擎已验收：启动少锡流程 → 缺数据分支 → 等待 PCB 焊盘异物检查 → 提交“否”继续翘曲检查 / 提交“是”命中异物路径 → 报告阶段。支持快照恢复、幂等及工单隔离。
- 模型 `azure-gpt-5_6-sol` 已通过真实 LLM + 原引擎两轮工具联调：读取状态、解释检查、创建待确认提议，未自动推进引擎。使用临时合成工单，不代表生产效果评测。
- 两个配置独立：`DEMO_MODE=scripted|live` 控制模型；`ENGINE_MODE=demo|bpmn-owl` 控制执行引擎。本机为 `live` + `bpmn-owl`。
- 当前引擎工单存到 `data-engine/`；旧模拟工单仍在 `data/`，不自动迁移，避免混淆执行语义。
- 原树的分支权重负责激活顺序，不是 Demo 自动学习历史频次。暂缓/无法判断不发送答案，不会推进到别的串行分支；任意优先排序明确拒绝。
- 原 CSV 缺少部分标准，此时页面警告并从树条件推导离线选项，不把它当作审核过的现场作业指导。未接数据的 UDF 优先返回树本身支持的“分析不可用”；其余 UDF 仅允许人工提供离线结果。

### 协作版体验顺序

本次更新扩展了引擎快照目录，旧工单保留但不跨版本推进，**请点“新建演示工单”**。

## 1. 直接运行

在当前这台电脑：

```bash

```

## 2. 两种模式，别混淆

| 模式 | 模型部分 | DSH 循环和插件 | 是否需要 Key |

## 3. 推荐演示路线

### 当前原引擎模式

1. 新建工单，观察 BPMN 已走到“故障树诊断”，自动记录明确显示“分析不可用”，而不是虚构 MES 结果。
2. 当前人工卡为“检测 PCB 焊盘异物”，选项沿用原标准中的“是/否”。选“无法判断”或暂缓后，引擎保持等待；恢复后可补交。
3. 选择“否”提交：原引擎继续激活“检测 PCB 翘曲状态”；若 CSV 缺少标准，卡片有醒目说明。
4. 新建另一工单，第一项选择“是”：原树输出“少锡 → 关键诊断数据缺失 → PCB 来料不可移动异物”路径，BPMN 进入报告阶段。该路径仍是树推断，不代替现场验证。
5. 刷新页面查看已提交结果和路径，导出报告。真实模型已验证自然语言生成提议；点击确认的完整浏览器联调需另行验证。

### 旧四任务模拟模式（`ENGINE_MODE=demo`）

### 工作台布局

- **左侧感知事件：** 展示本机已有工单，支持编号/当前任务搜索、进行中/检查完成筛选，以及工单切换；不填充虚假的客户工单。
- **中间诊断过程：** 工单概览与进度 → 可折叠的诊断结构概览 → 任务时间线。点击结构节点定位检查，展开任务后在该任务下面填写卡片，已完成/暂缓任务仍可查看。
- **右侧对话：** 保持原来的助手和提议确认界面。切换任务同步关联检查；切换工单加载该工单的对话、证据及待确认提议，未提交的表单和未发送文字在本次页面会话中分别暂存。
- “检查完成”仅指所有检查均已有明确结果，不意味着根因已经确认。结构图是演示检查关系，不是完整生产故障树。

### 操作顺序

1. **先看约束。** 点中间结构图的“钢网堵孔”，安全前置未完成时无法提交结果。
2. **直接操作卡片。** 在中间任务时间线展开“确认现场检查安全条件”，选择正常并提交。默认下一步是钢网，因为合成历史频次最高。
3. **解释检查。** 点“怎么检查”，DSH 调用 `explain_check`，展示配置的步骤、判据与来源。
4. **协商例外。** 点“暂时不能查”，或输入“现在不能检查钢网，先暂缓”。出现待确认提议，此时钢网仍为待检查。
5. **人工确认。** 点提议的“确认执行”。钢网变成暂缓，推荐切到锡膏记录；钢网原因并未被排除。
6. **记录异常。** 提交锡膏异常及演示说明。点击“推荐措施”，显示有来源、待工艺工程师审核的建议，不自动确认根因。
7. **自动分析。** 点“执行模拟分析”，查看固定合成样本的分布结果；无正常产量分母，不把分布当作不良率。
8. **追溯。** 展开操作记录、DSH 工具调用轨迹，导出 JSON 过程报告。刷新页面保留同一个工单。

其他演示语句：

- “先查锡膏批次” → 创建优先级调整提议，确认后改变当前推荐。
- “钢网检查结果正常” → 创建结果填报提议，确认前不写结果。
- “我感觉可能没问题” → 要求澄清，不生成正常结果。
- “下一步是什么？” → 根据当前持久化状态查询，不依赖旧聊天中的进度。

默认脚本仅为交互测试，不支持任意自然语言。这部分代码刻意放在独立的 `ScriptedAdapter`，切换真实模型不改诊断插件。

## 4. 实际分层

```text
浏览器任务卡 ── HTTP action ──→ 人工确认入口
                                  │
浏览器对话 ── HTTP chat ──→ DSH AgentLoop
                              │ native tool calls
                         DiagnosisPlugin
                              │
                 DiagnosisStore / 版本与幂等
                              │
                    EngineBridge / stdin JSON
                              │
               原 run_bpmn + 原 OWLExecutor（Python）
                              │
                  领域状态和引擎快照同文件提交
```

### 大模型拿到的工具

- `get_diagnosis_state`：当前任务、证据、前置条件、默认推荐。
- `explain_check`：当前动态任务的已配置提示与选项，缺标准明确标注。
- `propose_action`：暂缓、优先、结果填报的待确认提议。
- `search_measures`：旧模拟模式检索演示措施表；原引擎模式明确返回措施库未接入，不编造维修建议。

**没有 `confirm_action`、`execute_device` 或 `publish` 工具。** 提议确认是网页的独立 HTTP 动作，不交给模型。插件在每个 Agent 作用域注册，工单 ID 由服务端闭包绑定，不是模型参数。

### 旧模拟模式状态规则

- `pending`：待检查；`completed`：已有明确结果。
- `deferred`：暂缓；`needs_review`：无法判断、需要补查。
- 暂缓和未知均保留证据缺口，不转成正常。
- 现场钢网检查要求安全检查结果正常；只读批次记录和模拟趋势不需要现场检查前置。
- 默认排序用固定合成历史计数。**本 Demo 未实现线上历史统计学习或自动更新权重**；这里只展示消费优先级与个案调整的接口。
- 发现异常只输出异常证据，不自动宣布根因成立。
- 提交携带状态版本；过期卡片、过期提议拒绝写入。
- 最近 100 个 operationId 幂等：重复提交不再次改变状态，同 ID 不同内容拒绝。
- 同一工单的对话和 HTTP 动作串行，不同工单隔离。
- 一轮最多 6 个模型步骤。脚本模式整体超时 60 秒；真实模式默认至少 180 秒，可配置 `MODEL_TURN_TIMEOUT_MS`；CHJ 单次请求使用原仓库超时配置，普通兼容端点单次为 45 秒。`MODEL_MAX_TOKENS` 默认 4096。对话失败不会撤销已经确认的现场结果。

| `act(run)` | 生产 UDF 未接，不允许用模拟值冒充；当前缺数据路径见页首 |
| `act(defer/resume)` | 外层保存未回答状态；不向原引擎伪造答案，不跳过串行前置 |
| `propose` | 已支持动态任务与原选项，保留人工确认与版本校验 |
| `search_measures` | 生产措施检索仍待接入 |

重要：若现有引擎不支持中间任务顺序调整，必须先改引擎可执行项与等待/恢复协议，**不是在 DSH 外面换个提示词就能实现**。

## 8. 明确的 Demo 限制

- 仅监听 `127.0.0.1`。无用户登录和组织权限，不要部署到公网或实际生产网。
- 单进程本地 JSON 快照，不具备分布式锁、数据库事务和生产级容灾。写临时文件再 rename，未做 fsync 持久化承诺。
- 业务状态与最近对话展示保存在 `data/`；DSH 原始事件在内存，重启后创建新 DSH 会话并注入领域快照和最近对话，不是完整事件重放恢复。
- 每次运行最多新建 30 个演示工单，单会话对话长度有限；工单文件不会自动删除。
- 已完成结果不支持覆盖修改，演示时新建工单。图片每张 1MB、最多两张；暂不支持视频、音频、多人分派、远程附件或 VLM。
- 旧模拟模式的历史频次、措施、自动分析是固定夹具；原引擎模式使用真实树结构但未执行生产分析，二者都不能作为上线指标或真实故障证据。
- 本地协议测试已覆盖兼容端点和原 CHJ 适配器的工具往返、权限失败与凭据不外泄。2026-10-19 真实模型两轮工具联调通过；尚未做系统性语义效果评测。一次提议工具调用被校验拒绝后由模型修正成功，不宣称所有首次调用均正确。
