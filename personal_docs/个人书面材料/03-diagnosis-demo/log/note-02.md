# 协作式诊断实施计划

**目标：** 在已实现的补查上，支持工程师提出假设、Agent 调用分析工具提供可追溯证据、指出缺口、人工确认专家结论结束诊断。

**架构：** 原 BPMN/OWL 保留为指导与推断轨道；独立 collaboration 状态管理假设、证据和专家结论。LLM 只能记录用户陈述、调用确定性分析和起草结论。确认结束仅通过带版本、幂等键、核对声明和署名的人工接口。结束后冻结诊断写入，不把未查项标正常、不改写原树快照，不控线或放行。

**技术栈：** 既有 TypeScript/DSH/Python/原生 UI；新增本地 JSON 合成样本，无新依赖。

**约束：** 实际 MES 未接。统计确实从本地样本计算，但所有样本、统计、验证演示必须显著标注非生产数据；关联和更换后改善都不自动等于因果。

## 文件与顺序
- [ ] `tests/collaboration.test.ts`：先红灯验证分母计算、空样本与缺组处理、假设/证据来源、无验证不能起草专家结论、跨工单引用拒绝、确认前不结束、过期与幂等、结束后冻结、未查项与原快照保留。
- [ ] `src/collaboration.ts` + `fixtures/pcba-verification.json`：类型/schema、批次不良率与换料前后统计、确定性证据缺口简报；样本使用独立演示编号，不能声称从本工单真实 MES 取数。
- [ ] `src/diagnosis.ts`：工单内保存协作状态、记录假设/分析/人工验证、起草与确认专家结论、版本与只读结束状态。
- [ ] `src/diagnosis-plugin.ts` + `src/runtime.ts`：开放协作工具，明确观测/假设/证据/结论区别，输出支持和反对证据，不能自动结束。
- [ ] `src/server.ts` + `public/*`：人工确认 API、假设/证据/缺口面板、分析入口、专家确认及报告；原树改为辅助视图。
- [ ] 全量测试、真实模型两条链路（暂缓＋补查，提出假设＋统计＋人工验证＋专家出口）、浏览器复核与服务重启、更新项目记录。

## 决策记录
- 用户已确认协作模式并要求直接继续开发，不重复询问方案。
- 合成数据用来演示工具减轻取证劳动，不补造生产集成和收益指标。
- 工程师可以带已知局限结束诊断，界面展示全部本假设证据及未查项；Demo 署名非企业身份鉴权。
- 不开放任意深层设备操作；树外线索可登记假设与验证记录，正式补查仍遵循已有门禁。
