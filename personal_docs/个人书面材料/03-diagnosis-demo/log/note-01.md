# 工单结束后的故障树补全

已确认需求：仅树外结论触发候选路径，第一次人工确认更新草稿，第二次人工确认本地发版。不是实际生产发版。

实施选择：结单表单加“已覆盖/未覆盖/不确定”；未覆盖将生成任务与结单一起持久化。后台复用 DSH 和当前模型，通过受限工具提交结构化路径，不执行模型生成的代码。路径只能挂在原树已有非叶节点，步骤保留证据引用及“已有记录/建议补充”区别。人工编辑及确认标准后形成锁定草稿；发布时校验版本冲突，在 Demo 本地保存增量版本。新工单通过 Python 原 OWL 类加载增量分支，旧工单绑定原版本。

文件：`src/knowledge-types.ts`（schema）、`src/knowledge.ts`（生成状态、审核、发布）、`src/diagnosis.ts`（结单及版本绑定）、`src/runtime.ts` / plugin / server（生成和API）、`engine/worker.py`（安全JSON增量）、`public/*`（状态及两次确认）。

验证：未覆盖才触发；生成失败不撤销已结单；模型不能审批发布；伪造锚点/证据和不完整标准拒绝；并发/重复生成及发版幂等；发布前新工单不变，发布后原引擎实际可走新增路径，旧工单保持旧版本；浏览器验证完整流程。

限制：单机JSON、本地演示发布、无企业身份鉴权；仅追加分支，不删改原生产仓库；已有原树标准缺项仍明确警告，本次新增标准必须人工核对。版本冲突不静默合并。

已实现：独立 DSH 生成会话，仅注册 submit_knowledge_path；HTTP 后台任务与恢复；中间列状态卡、候选编辑及两阶段人工确认；本地版本装配与新旧工单隔离。验证包括真实模型合成数据联调、实际原引擎新增路径、失败重试与模型越权拒绝、浏览器完整操作。自动任务不伪造用户发言。
